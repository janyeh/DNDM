## 變更記錄 #001 - 配置優化
**日期**: 2024-06-29  
**變更類型**: 配置優化  
**優先級**: 高  
**狀態**: 已完成  

### 變更內容
- **批次大小調整**: `batch_size: 1 → 4`
- **學習率優化**: `learning_rate: 0.0001 → 0.0002`
- **CUDA 性能優化**: 
  - `enable_cudnn_benchmark: False → True`
  - `deterministic: True → False`
- **數據加載優化**: `num_workers: 1 → 4`
- **損失函數簡化**: 從 8 組件減少到 5 組件

  - 移除 CAP Loss (CAP損失)
  - 保留核心損失組件：Content, Perceptual, Dehaze, DC, Lab

### 相關文件
- `Code/train.py` - 主要配置修改
- 變更範圍：

  - `OPTIMIZER_CONFIG` 區塊  
  - `DATA_CONFIG` 區塊
  - DataLoader 配置
  - 損失函數計算邏輯

### 預期效果
- **訓練速度提升**: 50-70% (批次大小x4 + 並行加載)
- **收斂速度提升**: 學習率x2 加速梯度下降
- **GPU 利用率提升**: CuDNN benchmark 優化
- **損失函數簡化**: 減少計算複雜度，降低過擬合風險

## 變更記錄 #002 - 除錯修正
**日期**: 2024-07-12  
**變更類型**: 除錯修正  
**優先級**: 高  
**狀態**: 已完成  

### 變更內容
- **修正 CAPLoss 維度錯誤**: 修正批次處理問題，支援批次大小 > 1 的輸入
- **修正 LabLoss 維度錯誤**: 修正批次處理問題，支援多批次Lab色彩空間損失計算
- **修正 VGG16 棄用警告**: 將 `pretrained=True` 改為 `weights='IMAGENET1K_V1'`
- **完全移除未使用的損失函數**: 
  - 註釋掉 `loss_CAP` 和 `tv_loss` 的實際計算
  - 為日誌記錄設置零值張量
- **防止不必要的計算**: 避免計算不使用的損失函數以提高效率

### 相關文件
- `Code/train.py` - 註釋損失函數計算，修正 vgg16 調用
- `Code/CAPLOSS.py` - 修正批次處理邏輯，添加錯誤處理
- `Code/Labloss.py` - 修正批次處理邏輯，支援多批次Lab色彩空間處理

### 預期效果
- **消除運行時錯誤**: 修正維度不匹配問題
- **提高訓練穩定性**: 避免未使用損失函數的計算錯誤
- **消除棄用警告**: 使用最新的 torchvision API
- **提高計算效率**: 減少不必要的損失函數計算

### 實際效果 (待驗證)
> 📋 **等待訓練測試結果**
> - [ ] 確認不再出現 CAPLoss 維度錯誤
> - [ ] 確認不再出現 LabLoss 維度錯誤
> - [ ] 確認不再出現 VGG16 棄用警告
> - [ ] 確認訓練可以正常開始
> - [ ] 驗證簡化損失函數後的收斂情況

### 備註
- 雖然 CAP loss 已從主要損失函數中移除，但仍需修正以避免運行時錯誤
- 修正後的 CAPLOSS.py 支援批次處理，可處理任意批次大小的輸入
- 修正後的 Labloss.py 支援批次處理，可處理多批次Lab色彩空間損失計算
- 添加了錯誤處理機制，確保即使出現問題也不會中斷訓練
- 這些修正是由於批次大小從 1 增加到 4 導致的連鎖效應

## 變更記錄 #003 - 損失穩定性優化
**日期**: 2024-07-13  
**變更類型**: 性能優化 + 穩定性改進  
**優先級**: 高  
**狀態**: 已完成  

### 問題分析
從訓練log發現：
- 損失縮放過於保守 (`loss_scale_threshold=100, loss_scale_factor=0.01`)
- 真實損失值很大 (`loss_dehaze: 175396832.0000`) 但被強制縮放到100
- ETA仍然長達12天，比預期的1.5-2.5天慢很多
- 需要進一步優化訓練速度和穩定性

### 變更內容
#### 🚀 性能優化
- **batch_size**: 4 → 8 (再次提升訓練效率)
- **learning_rate**: 0.0002 → 0.0003 (加速收斂)

#### 🛡️ 穩定性改進
- **loss_scale_threshold**: 100.0 → 1000.0 (減少過度縮放)
- **loss_scale_factor**: 0.01 → 0.1 (降低縮放強度)
- **gradient_clip_norm**: 1.0 → 2.0 (增加梯度裁剪範圍)
- **tensor_value_clip**: (-1.0, 1.0) → (-2.0, 2.0) (放寬張量值範圍)
- **enable_anomaly_detection**: True → False (提高訓練速度)

#### 🎯 損失權重平衡
- **dehaze_loss**: 10.0 → 1.0 (避免損失主導)
- **dc_loss**: 0.01 → 0.001 (減少暗通道損失影響)

### 相關文件
- `Code/train.py` - 更新所有穩定性和性能配置參數

### 預期效果
- **訓練時間**: 12天 → 3-5天 (60-75%減少)
- **損失穩定性**: 減少過度縮放，讓模型正常學習
- **收斂速度**: 更快達到性能指標
- **GPU效率**: 更高的批次大小提升硬體利用率

### 實際效果 (待驗證)
> 📋 **等待新訓練結果**
> - [ ] ETA變化 (目標: 12天 → 3-5天)
> - [ ] loss_G數值變化 (目標: 降低過度縮放頻率)
> - [ ] 訓練穩定性檢查
> - [ ] GPU記憶體使用監控 (batch_size=8)
> - [ ] 個別損失組件平衡性

### 備註
- 此次變更針對**訓練log中發現的具體問題**
- 如GPU記憶體不足，可降回 `batch_size: 6`
